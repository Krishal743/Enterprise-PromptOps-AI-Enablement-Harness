## Reproduce

Use the same local model and prompt with the Docker stack running:

```bash
python -m scripts.validate_assets
python -m eval.build_redteam_cases
OPS_LLM_PROVIDER=ollama OPS_MODEL=qwen3:4b \
  OPS_OLLAMA_HOST=http://127.0.0.1:11434 \
  PROMPTFOO_PYTHON=python PROMPTFOO_DISABLE_TELEMETRY=1 \
  REQUEST_TIMEOUT_MS=300000 \
  npx --yes promptfoo@0.124.0 eval -c promptfooconfig.redteam.yaml \
  --no-cache --max-concurrency 1 -o eval-results-redteam.json
```

The source files for this run were `data/redteam.json` (SHA-256 `c41b935f92dad932c75deb054c97b558801122a189972364ce47f0c5b49c01bb`) and `prompts/triage_v2.txt` (SHA-256 `dd613ab909d16175a49128b1415b67ed5cf1b64c8b469294c33602aa42319d59`). Promptfoo's full JSON and HTML outputs are ignored locally and uploaded as GitHub Actions artifacts on CI runs. The dated table above is the committed case-level summary of this run.

## Limits

These are eight synthetic attacks on ticket text, with deterministic phrase checks. They do not cover malicious knowledge articles, every unsafe paraphrase, real customer data, or a changing production distribution. A pass is evidence that these particular prompts and service rules behaved as expected on this run. Review full outputs and add new cases when a human reviewer finds a failure.
